Semantics
- UI displays Status.diagnostics and player diagnostics only. No Cx::log,
  diagnostic bus emit or Editor::report_failure call is made for returned Status.
  Finished status is not a retirement authorization; only the original trusted
  bus row authorizes that. Backend publication-before-finished is relied on.
- Only ARA0935 schema=1/outcome=reloaded on a clean cursor page authorizes retiring
  older-sequence error rows 910..=912, matching exact world/player/source/binding
  and actual data.module in the successful modules batch. All other results,
  compile success, malformed metadata and missing provenance retain faults.
- Latest Store sequence is used, not first/count. An identical fault repeated
  after the marker becomes active again. Console records are never changed.
- Markers on incomplete cursor pages do not retire. A later clean exact marker
  can retire its scope/modules. Historical uncertainty remains explicit.
- Ledger bounded at 128 incarnations / 4096 module records. Overflow retains
  unknown faults and exposes a notice. Report is compact and does not copy logs.
- UI owns <=64 pending tickets / 8 finished statuses; polls <=8 tickets per 250ms
  in round-robin order. Requests coalesce per world and old-world ownership is
  retained to a matching terminal reply. Mismatched ticket/world cannot retarget.
- View mounts <=8 pending cards, 8 terminal cards, <=16 player rows per result and
  <=16 diagnostic rows per result. Extra results/diagnostics point to Console.
  Widget IDs use row indices to tolerate malformed duplicate-player results.
  Painting borrows retained state; it does not temporarily remove owned tickets.
- Idle/start/restart availability is explicit. Paused live Play may recover.
  No approval modal, restart fallback, inferred success or timeout-to-success.
