Ara — research synthesis & decision record

v2 · 2026-10-23 · Built from 10 research reports (R01–R10, Claude Opus 5.5 + GPT-6.1 Sol) and your decisions during the research. Full text: docs/research/00-synthesis.md · decision log: docs/decisions.md · plan: docs/plan/milestones.md. The research used the working name "snengine"; the engine is now Ara.

The answer. Ara is a Rust engine whose real API is a typed schema + command/query system over a text-first world. The native editor, the ara CLI, C# gameplay code, AI agents (via MCP) and the netcode are all clients of that one core. Every edit is a typed, undoable, attributed, reviewable command; every asset is diffable text with stable IDs; the simulation is fixed-tick and deterministic enough to test, replay and network.

Rendering runs on our own thin Vulkan 1.3 + Metal 4 layer with Slang shaders. One native UI system (UI Toolkit-like: web-shaped, not a browser) draws the editor, HUDs and world UI. C# is the single scripting language (confirmed), with measured sub-100 ms hot reload on your machine. Rust is the Burst-class tier for hot systems. Multiplayer is server-authoritative with selective prediction, built in from day one.

Same layering as Unity (native core → UI Toolkit → C#), rebuilt in Rust and designed around agents from the start. Nothing is cut; the roadmap is build order only.

Entitiesbevy_ecs tables: tight per-type component arrays in chunks, plain struct components, built-in change ticksBy design
JobsSystems declare reads/writes and run in parallel automatically. Safety is checked at compile time in Rust; C# systems get generated read/write sets. Chunk batches spread across cores.By design
BurstRust is the Burst tier: the same LLVM backend, &mut gives no-alias, glam gives SIMD. C# uses RyuJIT plus explicit Vector128/Vector256 and NativeAOT.C# gap measured: 1.74 vs 1.09 ns/entity on a scalar loop

A Burst-like compiler for a C# subset through LLVM is in the build order (M4). Spike S8 decides whether it's needed by benchmarking Unity DOTS, bevy_ecs, C# JIT and C# NativeAOT on four workloads.

Build order

Phases are dependency order. Nothing is dropped.

0 · Spikes

S1–S7 above.

1 · Kernel

Schema DB · documents / ops / undo · Engine Protocol, CLI, MCP · file formats · asset pipeline and cache · ECS with fixed tick and local sessions · C# host (L3 → L1) · diagnostics · capture and replay · ara-gpu Vulkan with a baseline renderer.

2 · Editor v0 + multiplayer foundations

Native UI runtime, docking, hierarchy, inspector, viewport and gizmos, assets, console, agents panel · play in a child process · Local / Host+N / Dedicated+N · replication and prediction · physics, audio, input · Outpost v0 (gray-box co-op), built largely by agents.

3 · Fidelity + authoring

Full render graph · material AST and graph editor · DDGI / RT · upscalers · reference path tracer · UI designer, stories, semantic tests · animation, navigation, VFX stacks · Metal 4 and the macOS editor · Linux.

4 · Scale + reach

GPU-driven scene · virtualized geometry · virtual shadow maps · streaming · terrain and foliage · HDR output · 2D toolset · full export to all five platforms with ara-bridge · mobile tier · C# performance tier from S8.

5 · UE-class and beyond

ReSTIR many-lights · layered materials · skin / hair · volumetrics · PCG · realtime path tracing · frame generation · rollback, lockstep, shared authority, host migration · visual scripting · Sequencer-class timeline · multi-user editing.

Hardest to change later

  1. Object model and identity (runtime / file / network IDs).
  2. Schema DB vocabulary and generation pipeline.
  3. On-disk formats and addressing.
  4. Mutation model and Engine Protocol.
  5. Simulation contract: fixed tick, input-driven, restorable state, scoped determinism.
  6. Rust↔C# ABI, with state only in ECS columns.
  7. RHI binding/sync model and shader pipeline.
  8. Material semantics (one AST for text and graph).
  9. UI runtime contract, one system for game and editor.
  10. Pack format, asset identity and platform floors.
