# Animation v2 integration

The production animation library stays independent of ECS, physics, rendering,
task pools and file I/O. The new `ara-anim-physics` adapter binds its narrow
traits to Jolt. `ara-anim-capture` is an offline verification binary.

## Fixed-tick runtime order

1. Resolve/cook skeletons, clips, rig maps, IK chains, motion databases and ragdoll
   profiles on import workers. Publish immutable generations at an allowed tick
   boundary. Construct each actor's scratch and snapshot buffers there.
2. Keep `Animator`, `TrajectoryPredictor`, `PhysicalState`, and any external input
   history in the character's ECS state. Programs/databases are immutable shared
   resources. Chain/FK/probe scratch and native body handles are derived caches.
3. Advance the predictor using the simulation's fixed dt. Predict the configured
   horizons, then use `FeatureWriter::write` and cached `ParameterId`s to populate
   the motion node's float query parameters. Positions and trajectories are in the
   actor's current local frame; rotate world velocity into that frame first.
4. Call `Animator::tick`. Apply returned root motion through the character
   controller. The node handles its own source clip time, root-cycle deltas,
   notifies, scalar curves and inertial history. Search is once per active node
   per simulation tick, including when a node is shared by cross-fading states.
5. Copy the output into the actor's preallocated working pose. Apply contacts in
   explicit order: `FullBody::solve`, `FullBody::look`, ground `FootPlacement`,
   then prop `HandGrip::solve`, according to the desired constraint priority.
6. Tick `PhysicalState`; submit `PhysicalAnimation::drive` using a short
   `JoltRagdoll::bind` borrow. Release animation/ECS borrows, then step physics.
7. Read/blend the post-physics pose, build model matrices and the skinning palette.
   Unmapped helper bones follow their animated parents. At zero physical weight,
   animation locals are copied exactly.
8. Checkpoint `Animator::snapshot_into`, predictor/input history and physical blend
   state with the same native physics snapshot. Restore all at the same fixed
   boundary. `Animator` serializes and validates motion-node history/offsets;
   ordinary sampler/FK caches do not affect authoritative replay.

## IK and retargeting

`Chain::cook` resolves consecutive joint IDs and validates bind-local limits.
FABRIK and CCD project rotations after each pass and retain segment lengths.
Cones use a circular swing bound plus signed twist; hinges discard swing entirely.
The work bound is integer iterations, never time. `SolveReport` exposes residuals.
Straight-chain singularities use a small deterministic bend seed.

`FullBody` couples contacts through bounded pelvis displacement and four ordered
projection sweeps. Higher numeric priority is restored last in each sweep; equal
priorities retain input order. It is an ordered iterative solver, and conflicting
goals do not have a global optimality guarantee. Foot probes are world-space rays;
actor transforms are rigid, walkable slopes are filtered, and sole normals are
converted back to model space. The Jolt adapter's closest-ray query retains stable
body/subshape tie ordering without collecting/allocating all hits.

`RigMap::auto` accepts Mixamo namespaces, UE-style thigh/calf/upperarm names,
Unity Humanoid names, explicit semantic metadata and unambiguous missing middle
joints. Ambiguity is an error; supply a typed explicit map. Partial rigs are legal.
`Retargeter` transfers model-space bind-relative rotation deltas, retains target
limb translations, scales root/hips by leg height and optionally corrects limb
endpoints using scaled bind-relative displacement. `bake` samples a source clip
at an explicit integer interval; compress the returned `ClipData` normally.
The metric in RESULTS is a moving-pelvis, planted-foot fixture, not a mocap claim.

## Motion database and node

`MatchConfig` defines source clip references, feature joints, future tick offsets,
sampling step and weights. Clips share a skeleton/timebase and are treated as
looping locomotion; future root samples extend through SE(3) cycles. The cooker
extracts six scalars per bone (root-relative position and velocity), three local
root-velocity scalars, then six scalars per horizon (position and facing).
Normalization uses population standard deviation with a 1 cm/unit floor and
square-root cost weights; SIMD padding is zero.

`MotionDatabase::to_bytes/from_bytes` provides a versioned, checksummed binary
asset-cache artifact; source settings stay canonical text. `normalize` and
`search` accept caller-owned buffers. Zero budget gives exact exhaustive SIMD
search; a finite budget deterministically samples rows across the whole database.
`SearchResult::exact` and `visited` expose the accuracy/work tradeoff. Ties select
the first sampled row. There is no wall-clock budget or nondeterministic early exit.

Use `NodeKind::MotionMatching`, place the database reference in `Node::clip`, and
configure `MatchNode::query` in the feature order above. Compile with
`Controller::compile_with_matching`; it checks source clip generations. Root
discontinuities do not teleport the actor on a search jump. The continuation
window avoids restarting clips for nearby matches; quaternion-log/log-scale and
translation offsets preserve pose/velocity and decay with a critically damped
spring. Only the incoming clip is evaluated after a jump.

The demo uses an explicitly synthetic eight-clip walk/run/strafe/turn/back/idle
set, 600 scripted input ticks, and a 1,000-character workload. It proves executable
data flow and reproducibility; it is not a substitute for production mocap review.

## Powered physical animation

`RagdollProfile` holds capsule geometry, parent connections, offsets, masses,
limits and bounded PD gains. `JoltRagdoll::spawn` creates real dynamic bodies and
hinge/six-DOF constraints in profile order. Shapes/setup allocate at boundaries;
successful warmed-up reads, forces, probes and blends allocate no Rust heap memory.

The existing Jolt backend exposes body force/torque commands rather than native
constraint-motor setters. Drives therefore use bounded world-space PD forces and
torques through those commands. Native constraints enforce the connections.
Hinges map directly; cones map conservatively to two six-DOF swing intervals
(swing/sqrt(2)), rather than exposing a native swing-twist motor API. Configure
collision layers explicitly; the tests disable intra-ragdoll layer collisions.

`PhysicalState::request` starts hit reactions, ragdoll/death or get-up over an
integer tick duration. Recovery powers bodies while reducing their pose weight.
The runtime chooses the face-up/down get-up animation and applies the
`get_up_root` reconciliation through its character controller. Save native
physics state alongside blend state; restoring only animation is insufficient.

## Canonical examples and reproduction

`cargo run -p ara-anim --example authoring_v2` regenerates four checked canonical
documents in `examples/documents`: IK setup, source/target humanoids, motion DB
configuration and powered-ragdoll profile. Creation and all feature edits use
`AnimationCommand` -> attributed `ara-ops` transactions -> canonical writer.
No editor/plugin side-channel document writes are introduced.

With `CARGO_BUILD_JOBS=2`, run:

```text
cargo run -p ara-anim --release --example procedural_v2
cargo run -p ara-anim --release --example motion_matching -- 100
cargo run -p ara-anim-physics --release --example powered
cargo run -p ara-anim-capture
```

The capture binary uses actual sampled/solved poses and the existing Vulkan
renderer to draw bone prisms. It captures walk, constrained hand reach,
cross-proportion retargeting, database-selected locomotion and real-Jolt recovery.
It has no skinned-mesh or production-character-art claim.
