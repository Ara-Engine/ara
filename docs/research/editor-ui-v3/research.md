# Ara editor and Hub: UI/UX research for the stillkit redesign

Research date: 2026-11-08. This is evidence for component specifications, not an implementation plan. **Documented** means an official manual, release note, design account, or API describes the behavior. **User report** means a particular person's experience; it establishes a failure mode, not its prevalence. **Ara proposal** means a design inference or initial test value, not a measured competitor default. Dimensions proposed here are logical pixels at 100% UI scale.

Finding IDs are stable references for the final forty rules. Versioned sources take precedence over rolling documentation. Several Blender pages were searchable but returned fetch errors; those findings use indexed official excerpts. No hands-on latency, hit-box, or frame-time measurements were performed. In particular, no evidence here establishes that a competitor handles 100,000 visible tree rows smoothly.

Local constraints checked: [decisions.md](../../decisions.md), especially D18, D24, D28, D30 and D31. Keep Ara's semantic themes, custom title bar, shared command registry, floating windows, and immediate attributed agent edits. Older milestone language about accepting agent changes does not override D24. Research does not reopen these decisions.

## 1. Editors and professional-tool precedents

### Unreal Engine 5.5–5.7

- **E01 — Details is a selection-dependent property workspace.** UE 5.5 puts the actor name above live property search; changed values receive a reset indicator, and edit conditions disable dependent settings. Ara should make selected identity, filtering, provenance, and disabled reasons distinct parts of the inspector instead of treating every row as an identical input. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-editor-details-panel-in-unreal-engine?application_version=5.5)
- **E02 — Favorites require version care.** UE 5.5 documents Details favorites as experimental, enabled in Editor Preferences, with some customized properties unsupported. They place starred properties at the top. This is evidence for persistent shortcuts to frequently edited fields, not evidence that every UE property has a polished favorites workflow. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-editor-details-panel-in-unreal-engine?application_version=5.5)
- **E03 — Outliners can be independently configured views.** Epic documents multiple Outliner instances, text filtering, and optional columns controlled from the column-header context menu. Ara can support a broad scene tree and a second narrowly filtered view without duplicating scene data; column customization should be optional and recoverable. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/outliner-in-unreal-engine)
- **E04 — Drawer and dock are separate interaction modes.** UE 5.5's Content Drawer opens with Ctrl+Space on Windows, dismisses on focus loss, and offers Dock in Layout; up to **four** Content Browser instances can coexist. Preserve location and filters when switching modes, and avoid making temporary dismissal destroy browsing context. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/content-browser-in-unreal-engine?application_version=5.5)
- **E05 — Correct the toolbar date: the major redesign is 5.6.** Epic explicitly contrasts the 5.6 toolbar with the earlier legacy toolbar. It occupies a separate strip above the viewport and groups transforms/snapping, camera, view modes, performance/scalability, and viewport options; narrow widths use overflow. Do not label this specific redesign as a 5.4 feature. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/viewport-toolbar?application_version=5.6)
- **E06 — Slate's useful precedent is selective invalidation.** Epic describes caching geometry and repainting invalidated widgets rather than unchanged content. This supports stillkit's change-driven design, but does not establish that Unreal's entire editor consumes zero CPU when idle. Ara's acceptance measurements must separate UI work from a live GPU viewport. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/invalidation-in-slate-and-umg-for-unreal-engine)

### Unity 6.0–6.6

- **E07 — Inspectors have deliberate multi-selection semantics.** Unity 6.0 displays common components, explains unsupported or absent components, and uses a dash for differing values. A mixed value is not zero or empty. Ara should expose the affected-object count and communicate partial applicability before a bulk edit. [Source](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-windows-views-reference/using-the-inspector/inspector-items)
- **E08 — Hierarchy v2 evolved across the requested range.** The 6.3 beta feedback thread describes a UI Toolkit rewrite with configurable columns; Unity's 6.6 announcement makes it default and lists large-scene improvements, reorderable columns, extension APIs, and non-GameObject items. Separate the 6.3 preview's problems from the later default product. [6.3 source](https://discussions.unity.com/t/feedback-on-the-new-hierarchy-panel-in-6-3/1685573), [6.6 source](https://discussions.unity.com/t/unity-6-6-is-now-available/1735357)
- **E09 — A tree need not display every column equally loudly.** Unity's new Hierarchy exposes visibility, picking, active, static, layer and tag columns; its documentation says non-default values are displayed. Optional alternating backgrounds aid scanning. Ara can emphasize exceptions while retaining discoverable controls for the default state. [Source](https://docs.unity.com/en-us/engine/6000.5/manual/unity-editor/editor-windows-views-reference/hierarchy-window/new-hierarchy)
- **E10 — Project browsing spans list and thumbnail workflows.** Unity offers one- and two-column arrangements, Favorites, search and type filtering. Its thumbnail slider reaches a hierarchical list at the far left. This is a useful continuous density model: names and metadata for bulk work, larger previews for visual identification. [Source](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/project-view)
- **E11 — Overlays are movable tools with explicit docking affordances.** Unity overlays have a grab handle and blue drop zones; top/bottom docking produces horizontal layouts, side docking vertical layouts. Floating overlays can overlap. Ara should spec collapse, overlap ordering, preset restoration and narrow-viewport behavior alongside the initial toolbar arrangement. [Source](https://docs.unity.com/en-us/engine/6000.5/manual/working-with-scenes/scenes-manage-gameobjects/overlays/position-and-display/position-overlay)
- **E12 — UI Toolkit's collection model is the relevant native precedent.** Its TreeView exposes fixed item height, persistent selected IDs, virtualization mode and drag callbacks. Ara should similarly separate stable model identity from recycled row views, allowing very large hierarchies without making widget lifetime equal entity lifetime. This is an architectural precedent, not a published 100k-row benchmark. [Source](https://docs.unity3d.com/cn/6000.0/ScriptReference/UIElements.TreeView.html)

### Godot 4.x

- **E13 — Inspector discovery combines search with documentation.** Godot's inspector supports case-insensitive subsequence matching: `vsb` can match Visibility. Property tooltips explain usage and script names; contextual actions expose documentation and property paths. Ara's reflected documentation can support both human-friendly labels and stable API identifiers. [Source](https://docs.godotengine.org/en/4.5/tutorials/editor/inspector_dock.html)
- **E14 — Inspector navigation should survive nested resources.** Godot provides back/forward history, a history list, resource editing, non-default expansion, and favorites. These are precedents for inspecting a material reached from an entity and then returning to the same entity and scroll position. Preserve selection context while opening referenced assets. [Source](https://docs.godotengine.org/en/4.5/tutorials/editor/inspector_dock.html)
- **E15 — Godot 4.6 is a layout and visual-design reference, distinct from 4.3.** Its release introduces movable, floatable docks and a Modern theme focused on reducing clutter; Classic remains available. Ara should provide a reliable default layout plus reset and migration paths when panel arrangements change between engine versions. [Source](https://godotengine.org/releases/4.6/)
- **E16 — Density can be a preference with a stated tradeoff.** Godot exposes horizontal vector editing, float-drag speed and folding preferences. Its docs explicitly warn that horizontal vectors are compact but make large values harder to edit without a wider inspector. Ara should adapt vector layout to actual width rather than compressing all axes unconditionally. [Source](https://docs.godotengine.org/en/4.4/classes/class_editorsettings.html)

### Blender 4.x/5

- **E17 — Areas are task surfaces rather than fixed-purpose slots.** Blender areas can change editor type, split/join, swap contents, maximize and duplicate into another OS window. The documented maximize shortcut is **Ctrl+Space**, not Shift+Space. Ara should borrow reversible focus and multi-monitor support without requiring Blender's corner gestures for basic docking. [Source](https://docs.blender.org/manual/en/4.5/interface/window_system/areas.html)
- **E18 — Properties uses explicit context.** Blender 5.0 groups scene/object/material settings into vertical tabs, showing relevant groups for the active data. Its release notes add scene/view-layer selectors and improve Move to Collection search. For Ara, distinguish entity components, scene settings, asset settings and tool settings visibly. [Manual](https://docs.blender.org/manual/ar/5.0/editors/properties_editor.html), [release notes](https://developer.blender.org/docs/release_notes/5.0/user_interface/)
- **E19 — Search and favorites make a large command system usable.** Blender's F3 Menu Search displays menu locations, while developer Operator Search includes otherwise hidden operators. Since 4.0, regular menus support Space to search, Add menus accept immediate typing, and recent searches can rank first. Do not conflate these two search scopes. [Manual](https://docs.blender.org/manual/en/4.0/interface/controls/templates/operator_search.html), [4.0 notes](https://developer.blender.org/docs/release_notes/4.0/user_interface/)
- **E20 — Modal tools turn precision work into a short dialogue.** Blender supports typed transforms, axis constraints, confirm/cancel, snapping and precision modifiers. Shift makes transforms **one tenth** as fast; Ctrl toggles snapping. Ara should show the active constraint and available modifiers in a stable status area while a gesture is active. [Source](https://docs.blender.org/manual/en/latest/scene_layout/object/editing/transform/control/precision.html?highlight=snap)
- **E21 — Outliner focus and selection are different states.** Blender documents blue selected rows and a lighter active row, Ctrl additive selection, Shift range selection and optional synchronization with other editors. Ara needs a stable active entity inside a multi-selection, with keyboard focus separately visible; active-object editing must not silently reduce the selection. [Source](https://docs.blender.org/manual/nb/4.5/editors/outliner/selecting.html)

### Professional tools

- **E22 — Figma's redesign is evidence for testing prolonged use.** UI3 initially floated panels and simplified controls; Figma later restored fixed but resizable panels and visible blend-mode labels because concealment slowed repeated work. Canvas space alone is an insufficient success metric: compare action count, pointer travel and value recognition during real authoring tasks. [Source](https://www.figma.com/blog/our-approach-to-designing-ui3/)
- **E23 — Linear derives visual hierarchy systematically.** Its redesign describes themes generated from **three inputs: base color, accent color, contrast**, replacing 98 individually specified variables. This supports semantic surfaces and restrained accents in Ara; it does not imply copying Linear's exact palette or discarding Ara's existing theme contract. [Source](https://linear.app/now/how-we-redesigned-the-linear-ui)
- **E24 — Zed keeps commands and appearance accessible.** Its palette uses Cmd/Ctrl+Shift+P and namespaced actions such as `workspace: new file`; UI, code and agent typography are configurable. Ara can expose the same stable command identity through menus, shortcuts, the palette and agents while letting long-form agent text differ from dense property labels. [Palette](https://zed.dev/docs/command-palette), [appearance](https://zed.dev/docs/visual-customization)
- **E25 — Rider's New UI includes a compact option.** Compact mode reduces toolbar/header heights, padding, spacing, icon and button sizes; distraction-free and Zen modes serve different purposes. Offer density and focus as separate controls. Fleet is historical inspiration: JetBrains ended its distribution on **December 22, 2025**, so it is not a current product recommendation. [Rider](https://www.jetbrains.com/help/rider/IDE_Viewing_Modes.html), [Fleet](https://blog.jetbrains.com/fleet/2025/12/the-future-of-fleet/)
- **E26 — Houdini creates in context.** Tab searches available nodes for the current network; dropping a new node onto a wire inserts it, and starting from a connector can create an attached node. Its network editor also offers quickmarks, a conditional minimap and edge panning during dragging. Ara graph tools should preserve context between search and placement. [Creation](https://www.sidefx.com/docs/houdini/network/nodes.html), [navigation](https://www.sidefx.com/docs/houdini/network/navigate.html)
- **E27 — Resolve exposes task workspaces without fragmenting the project.** The Media, Cut, Edit, Fusion, Color, Fairlight and Deliver pages organize a continuous workflow. Resolve 20.1 extends **Shift+Space effects search** across additional pages and improves small/dual-screen layouts. Ara can use task-oriented layout presets while retaining common navigation and commands across them. [Official guide](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Editors-Guide.pdf?_v=1757574010000), [20.1 notes](https://documents.blackmagicdesign.com/SupportNotes/DaVinci_Resolve_20.1_New_Features_Guide.pdf?_v=1756105210000)
- **E28 — Painter keeps asset discovery adaptable.** Its Assets panel can dock vertically or horizontally, open sub-library windows, collapse type filters at reduced widths, and use Small/Medium/Large/List views. Materials can be dragged into the layer stack to create layers. This is evidence for responsive, semantically valid drop targets rather than one giant undifferentiated asset grid. [Layout](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/interface/assets/customizing-the-layout), [layers](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/interface/layer-stack/creating-layers)

## 2. Launchers: project lists, templates, versions and onboarding

- **L01 — Unity Hub's project table emphasizes recognition and recovery.** Rows include name/path, favorite status, modified time and editor version; typing searches names and paths, and extra details expand below a row. Ara should show path disambiguation for same-named projects and keep launch/version actions accessible without expanding every row. [Source](https://docs.unity.com/en-us/hub/projects-window-reference)
- **L02 — Match version recovery to the project.** Unity Hub offers installed versions or installation of another version when the saved version is missing. Changing versions can trigger script updates and library rebuilding. Ara should explain the pinned version, compatibility and expected work before launching a substitute, with an immediate Install required version action. [Source](https://docs.unity.com/ja-jp/hub/project-manage)
- **L03 — Templates are compatibility-filtered choices.** Unity's creation flow chooses an editor first, then compatible Core, Sample or Learning templates. Ara's template cards should state purpose, engine compatibility, downloaded state and resulting project location; name/path validation should happen before creation starts. Keep a small blank starter alongside richer samples. [Source](https://docs.unity.com/en-us/hub/project-create)
- **L04 — Side-by-side installations need component visibility.** Hub manages multiple editors plus optional platform/language/developer modules, including locating an existing installation. Ara should distinguish missing engine, missing export prerequisite and unavailable project path; these are different repair actions, not a single generic launch error. [Source](https://docs.unity.com/en-us/hub/install-editors), [modules](https://docs.unity.com/en-us/hub/add-modules)
- **L05 — Cached rows can precede expensive discovery.** Unity Hub 3.19.5 reports **40% faster startup in Unity's benchmarks** and immediately presents recent-project snapshots while other data loads. Treat the number as vendor-reported, not an Ara target. Ara can render cached local rows first and refresh branch/size/cloud metadata without blocking Open. [Source](https://discussions.unity.com/t/now-available-unity-hub-3-19-5/1724580)
- **L06 — Project lists also need virtualization.** Unity Hub 3.21.1 explicitly describes rendering only visible rows to improve scrolling, filtering and expansion; it also introduces project tags. Ara should use searchable tags and virtualized rows from the first large-list design, even though most users begin with only a few projects. [Source](https://discussions.unity.com/t/now-available-unity-hub-3-21-1/1734183)
- **L07 — Epic makes engine versions concrete installation objects.** The UE Library adds an engine tile with a **+** action and selects a version from that tile. This communicates side-by-side versions well; Ara should additionally make per-project compatibility visible directly in the project row, rather than requiring users to infer it from a separate installed-engine gallery. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/install-unreal-engine)
- **L08 — Toolbox prioritizes quick return to work.** Favorite projects pin to the top, search finds them, and one click opens the appropriate IDE. Its keyboard navigation includes **Ctrl+2** for Projects. Ara Hub should give recent/favorite projects a predictable keyboard path, with launch errors attached to the attempted project. [Product](https://www.jetbrains.com/toolbox-app/), [keyboard navigation](https://www.jetbrains.com/help/toolbox-app/keyboard-navigation.html)
- **L09 — Rollback has a visible storage cost.** Toolbox keeps previous tool versions for instant rollback, with cleanup controls and explicit loss of instant rollback when removed. Ara's engine manager should display installed size, projects using each version, and whether removing a version removes a useful recovery option. [Source](https://www.jetbrains.com/help/toolbox-app/frequently-asked-questions.html)
- **L10 — Godot 4.3's redesign favors direct local operations.** Its Project Manager supports create/import/edit/play, project tags, ZIP import, theme/scale settings, and empty-folder validation. Online demos require explicitly going online. Ara should keep local creation/opening useful before any samples, learning content or network requests finish loading. [Manual](https://docs.godotengine.org/en/4.3/tutorials/editor/project_manager.html), [4.3 release](https://godotengine.org/releases/4.3/)
- **L11 — Blender's splash is a lightweight launcher, not an engine manager.** It provides templates, recent files and recovery; Esc or clicking outside dismisses it into the editor. The first-run flow can import previous preferences. Ara's editor welcome surface can be similarly dismissible while Hub retains explicit multi-version/project management. [Splash](https://docs.blender.org/manual/en/4.5/interface/window_system/splash.html), [first-run defaults](https://docs.blender.org/manual/en/4.5/getting_started/configuration/defaults.html)
- **L12 — Steam's library solves a different discovery problem.** Dynamic collections use tags/filters and custom shelves foreground recent or favorite games. Borrow saved collections and a recent-work entry point for many projects, but make artwork optional: a production launcher also needs readable paths, versions and operational state. This is an Ara inference, not a Valve productivity claim. [Source](https://store.steampowered.com/libraryupdate)
- **L13 — Offline creation must remain discoverable.** Unity's Hub 3.13.1 announcement explains that offline project creation was removed, reinstated, then made easier to find after confusion. Ara should present local creation as a normal primary flow and put optional account/network services behind explicit choices. [Source](https://discussions.unity.com/t/hot-off-the-presses-hub-3-13-1-now-available/1667412)

## 3. Real user pain points and failure modes

- **P01 — Unity 6.3: columns can damage basic navigation.** In a **20-post** feedback thread, CiroContns reports “No Enter to rename on Mac” and names truncated despite unused space; a Unity responder discusses Finder-like name-column expansion. Ara should prioritize names, platform rename conventions and automatic fitting over displaying extra columns. [Source](https://discussions.unity.com/t/feedback-on-the-new-hierarchy-panel-in-6-3/1685573)
- **P02 — Unity 6.3: incorrect selection is a correctness failure.** The same thread reproduces Scene/Hierarchy disagreement after recompilation; Unity later says it reproduced and fixed the bug for stable 6.3. This is historical beta evidence, not a claim that 6.6 still fails. Keep selection keyed by entity identity across reloads and recycled rows. [Source](https://discussions.unity.com/t/feedback-on-the-new-hierarchy-panel-in-6-3/1685573)
- **P03 — Unity Search: refresh must not steal gestures.** UUM-132992 reports dragging a Transform field losing focus when background search refreshes; reproduction includes 6.0 and 6.3. Ara should defer disruptive result replacement until mouse-up or text commit, keeping the edited entity and field stable meanwhile. [Source](https://issuetracker.unity.com/issues/10480/changing-transform-values-in-search-window-inspector-loses-focus-while-dragging-and-stopping-mouse-without-releasing-dragging-action)
- **P04 — UE/UEFN toolbar: redesign can increase travel and decoding effort.** Punkcat reports “white on black small icons increase squinting” and “Moved tools to opposite sides”; another participant prefers the old placement. This UEFN thread concerns shared toolbar changes, not a controlled UE5 study. Test recognition and pointer travel before rearranging familiar controls. [Source](https://forums.unrealengine.com/t/new-toolbar-feedback/2568289)
- **P05 — UE 5.6: old tutorials become navigation traps.** A user cannot find the old hamburger menu or FPS display after the toolbar redesign. Ara should retain searchable command names and aliases when moving controls, and let help identify the installed editor version. [Source](https://forums.unrealengine.com/t/two-small-questions-about-the-viewport-toolbar/2652566)
- **P06 — UE Content Browser: visual previews can coincide with severe slowdown.** One report says “my framerate tanks to 12fps” from 120 when opening the browser; a responder suggests disabling real-time thumbnails. This does not establish the cause. Ara should benchmark browser opening with live rendering and bound preview work independently of row count. [Source](https://forums.unrealengine.com/t/horrible-fps-after-opening-content-browser/2000798)
- **P07 — UE Details/content scrolling: respect input preferences.** A user requests faster scrolling through long lists and reports Windows wheel settings having no effect. Ara should preserve OS wheel/trackpad behavior and expose an editor multiplier if needed, rather than making users compensate for a hardcoded speed. [Source](https://forums.unrealengine.com/t/increase-mouse-scroll-speed-in-content-browser/2026732)
- **P08 — Godot: search needs a direct keyboard path.** Proposal #14617 describes requiring dock navigation plus extra arrow presses before filtering; the author wants shortcuts directly to tree/inspector search. Ara should provide Focus hierarchy search and Focus property search as first-class bindable commands. [Source](https://github.com/godotengine/godot-proposals/issues/14617)
- **P09 — Godot: precision and accidental scrolling conflict.** In #2099 a user says dragging is “too fast for changing a frame number”; discussion raises the risk of wheel edits while intending to scroll the inspector. The older report is motivation, not a current-version diagnosis. Ara should use typed steps and focused-only wheel edits. [Source](https://github.com/godotengine/godot-proposals/issues/2099)
- **P10 — Blender: automatic reveal can fight deliberate browsing.** A 2026 Outliner design thread debates Scroll to Active and Expand on Focus, including the preference: “Personally I use ‘show active’ in the outliner”. Ara should distinguish synchronization, reveal and focus; explicit Reveal selected should always exist, while automatic scrolling should be configurable. This is later Blender 5.x feedback. [Source](https://devtalk.blender.org/t/outliner-should-we-focus-expand-on-selection/45781)
- **P11 — Figma: hiding values increases repeated effort.** Figma's own UI3 retrospective says icon-only blend modes “forced users to wait for a tooltip”. The team restored labels and fixed resizable panels. Ara's compact inspector must retain current enum/value text; tooltips should explain controls, not be required to read their state. [Source](https://www.figma.com/blog/our-approach-to-designing-ui3/)
- **P12 — Scaling must include icons and geometry.** Zed issue #7820 includes users wanting icons scaled independently because text was readable but icons remained small. Painter users likewise request in-app scaling; one reports “the UI is just too small”. Ara must test complete layouts at enlarged scale, not merely change the font token. [Zed](https://github.com/zed-industries/zed/issues/7820), [Painter](https://community.adobe.com/feature-requests-60/substance-painter-and-designer-would-like-to-see-the-ability-to-adjust-the-ui-scale-while-in-app-1553706)
- **P13 — Dense-tool users still need comfort controls.** JetBrains publishes instructions specifically for making New UI more compact; a SideFX user asks how to enlarge Houdini fonts and buttons. Opposite requests are compatible: support independent density and UI scale instead of assuming either spaciousness or tiny controls universally wins. [JetBrains](https://youtrack.jetbrains.com/articles/SUPPORT-A-650/How-to-make-the-new-UI-more-compact-so-there-is-less-empty-space), [Houdini](https://www.sidefx.com/forum/topic/86183/)
- **P14 — Hub metadata must not gate opening.** In a long Hub 3.17.3 discussion, a user reports waiting **20–30 minutes** for branch fields before projects open, and suggests querying on expansion. This is a report, not a measured general startup time. Ara should allow opening from cached identity independently of optional repository inspection. [Source](https://discussions.unity.com/t/now-available-unity-hub-3-17-3/1716556?page=2)
- **P15 — Launcher discovery needs a bounded failure state.** Epic users report their UE library stuck on Please Wait/Discovering Content despite attempted recovery. Ara should retain known projects and versions, show per-item failures, and offer Retry/Locate/Open folder instead of replacing all useful content with an indefinite spinner. [Source](https://forums.unrealengine.com/t/epic-games-launcher-unreal-engine-library-stuck-on-please-wait-and-discovering-content/2744816)
- **P16 — Resolve: scaling regressions can affect menus as well as text.** A firsthand Resolve 17 critique reports fonts/icons “practically unreadable” on small high-DPI displays, then describes disappearing context menus after scaling changes. This is historical user evidence, not a claim about Resolve 20/21. Ara's scaling checks should include popups, detached windows and mixed-DPI monitors. [Source](https://gh0.st/fixing-ui-font-size-in-davinci-resolve/)

## 4. Interaction details for component specifications

### Number fields and vectors

- **I01 — Give scrubbing and typing distinct entrances.** Unity documents direct numeric entry and dragging the property label; Blender allows dragging number fields, Ctrl snapping, Shift precision and Tab/Shift+Tab traversal. Ara proposal: drag the label or dedicated scrub area; a normal value click enters text. A small pointer movement must not accidentally start an edit. [Unity](https://docs.unity.cn/6000.1/Documentation/Manual/EditingValueProperties.html), [Blender](https://docs.blender.org/manual/en/4.2/interface/controls/buttons/fields.html)
- **I02 — Pixels per unit must follow property semantics.** Epic exposes `LinearDeltaSensitivity` as mouse movement divided by sensitivity and multiplied by Delta; Godot exposes float-drag speed. Neither establishes a universal editor default. Ara proposal: start at **8 logical px per schema step**, Shift **0.1×**, Alt **10×**, Ctrl quantization; validate separately for meters, degrees, frames and large magnitudes. [Epic API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Slate/SSpinBox/FArguments/LinearDeltaSensitivity), [Godot](https://docs.godotengine.org/en/4.4/classes/class_editorsettings.html)
- **I03 — Support continuous adjustment without screen-edge dead ends.** Blender's Continuous Grab warps relative pointers within the view, with tablet restrictions. Ara proposal: use relative input/wrapping where supported, preserve the original cursor location on release, and provide a non-warping tablet/remote-desktop path. Edge wrapping must not change the accumulated value unexpectedly. [Source](https://docs.blender.org/manual/en/4.5/editors/preferences/input.html)
- **I04 — Expressions reduce calculator detours.** Unity accepts expressions including `2*pi`, trigonometric functions and multi-object distributions such as `L(a,b)`; Blender evaluates arithmetic in numeric fields. Ara should support a documented, bounded expression grammar, show validation before commit, and retain the original value on error. Unity's random-expression feature need not become an implicit nondeterministic Ara edit. [Unity](https://docs.unity.cn/6000.1/Documentation/Manual/EditingValueProperties.html), [Blender](https://docs.blender.org/manual/en/4.2/interface/controls/buttons/fields.html)
- **I05 — Units belong to input and presentation.** Blender distinguishes display units from internal values, supports metric/imperial formats, and documents representations such as `2m 28.5cm`. Ara proposal: accept `25cm`, `2m`, `90deg` and `0.5s` only for compatible schema units, normalize on commit, and explain incompatible suffixes inline. [Source](https://docs.blender.org/manual/ar/4.5/scene_layout/scene/properties.html)
- **I06 — Linked vectors need visible semantics.** Godot uses a chain icon for linked values; Unity documents a limitation for math expressions with constrained multi-selection scale. Ara proposal: chain scale ratios, leave translation unlinked by default, and define behavior for zero axes and mixed values before implementing the toggle. A chain must never ambiguously mean both equal values and preserved proportions. [Godot](https://docs.godotengine.org/en/4.5/tutorials/editor/inspector_dock.html), [Unity](https://docs.unity.cn/6000.1/Documentation/Manual/EditingValueProperties.html)
- **I07 — Mixed and default states are independent.** Unity's dash communicates differing selected values; UE exposes reset indicators for values differing from defaults. Ara should preserve both states, offer Reset all selected, and distinguish typing an absolute value from dragging a relative delta. The relative-delta policy is a proposal requiring tests, not a documented Unity guarantee. [Mixed values](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-windows-views-reference/using-the-inspector/inspector-items), [defaults](https://dev.epicgames.com/documentation/en-us/unreal-engine/level-editor-details-panel-in-unreal-engine?application_version=5.5)
- **I08 — Consider a precision ladder for advanced work.** Houdini's middle-button value ladder changes magnitude vertically and value horizontally, and works on labels, individual components and numbers within expressions. Ara can offer this as an optional advanced affordance; ordinary scrubbing and typing must remain sufficient for a two-button mouse or trackpad. [Source](https://www.sidefx.com/docs/houdini/basics/ladder.html)

### Trees and large lists

- **I09 — Specify the complete keyboard model.** WAI's tree pattern defines Up/Down among visible rows, Right expand/first child, Left collapse/parent, Home/End, and type-ahead, recommended especially beyond **seven root nodes**. Ara should expose one tab stop for the tree and preserve its last active row when focus returns. [Source](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)
- **I10 — Multi-select needs a durable anchor.** Blender documents Ctrl additive selection, Shift ranges, and Ctrl+Shift extending ranges. Ara should keep the active row and range anchor stable during scrolling, filtering and drag initiation; context actions should target the existing selection when right-clicking an already selected row. The final clause is an Ara proposal. [Source](https://docs.blender.org/manual/nb/4.5/editors/outliner/selecting.html)
- **I11 — Rename must honor platform habits.** Godot documents F2 on Windows/Linux and Enter for macOS project rename. Ara proposal: support F2 and native macOS Return, inline selection of the editable name, Enter commit and Escape cancel, without changing selection or scrolling unexpectedly. [Source](https://docs.godotengine.org/en/4.6/tutorials/editor/default_key_mapping.html)
- **I12 — Differentiate before, after and inside drops.** Godot's Tree API defines on-item and in-between zones; combining them leaves the central half for inside and outer portions for before/after. Ara should draw insertion lines with an indentation cue and a distinct parent highlight, reject cycles, and make illegal drops visibly unavailable. [Source](https://docs.godotengine.org/en/4.6/classes/class_tree.html)
- **I13 — Hover expansion and edge scrolling complete drag-and-drop.** Godot can unfold rows while dragging over them; Houdini documents edge panning while moving nodes. Ara proposal: **600 ms** spring expansion and a **24 px** edge-scroll band with speed proportional to penetration. These are initial test values; stop both immediately on cancellation or pointer exit. [Tree](https://docs.godotengine.org/en/4.6/classes/class_tree.html), [edge-panning precedent](https://www.sidefx.com/docs/houdini/network/navigate.html)
- **I14 — Virtualize views, not identity.** Unity TreeView creates/rebinds item views and retains selected IDs. Ara proposal: benchmark **100k total rows**, deep nesting, multi-selection, filter changes and a held drag; instantiate only visible rows plus overscan. Track row-bound work, allocations and input latency rather than claiming success from one fast initial render. [Source](https://docs.unity3d.com/cn/6000.0/ScriptReference/UIElements.TreeView.html)
- **I15 — Filter results should retain location.** Epic's skeleton tree explicitly offers hierarchy-preserving versus flattened filtering and grayed parent rows. Ara proposal: retain ancestors by default, emphasize matching labels, count results, and restore pre-filter expansion/scroll when clearing. Reparenting under a filtered view must show the actual destination unambiguously. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/physics-asset-editor-in-unreal-engine---skeleton-tree)
- **I16 — Avoid global tree rebuilds for visual changes.** Blender's developer documentation distinguishes redraw from rebuilding an expensive Outliner tree. Ara should update selection, hover and activity badges independently of hierarchy structure; background agent updates must not force every row to rebind or reset the scroll anchor. [Source](https://archive.blender.org/wiki/2024/wiki/Source/Interface/Outliner.html)

### Docking, splitters and layouts

- **I17 — Drag thresholds are a platform setting, not a competitor constant.** Qt recommends the system start-drag distance and gives a **10 px fallback** where the platform supplies none. Ara should use platform thresholds for tabs and list drags, then verify high-DPI and touchpad behavior. No verified Unity/UE-specific threshold was found. [Source](https://doc.qt.io/qt-6.8/qapplication.html)
- **I18 — Compare explicit guides with edge previews.** Visual Studio shows a docking guide diamond and a shaded destination preview; Unity shows panel outlines and blue overlay drop zones. Ara proposal: central **five-way** targets for tab/left/right/top/bottom docking plus full destination shading, with edge targets for root splits. Keep targets stationary during a drag. [Visual Studio](https://learn.microsoft.com/visualstudio/ide/customizing-window-layouts-in-visual-studio?view=visualstudio), [Unity overlays](https://docs.unity.com/en-us/engine/6000.5/manual/working-with-scenes/scenes-manage-gameobjects/overlays/position-and-display/position-overlay)
- **I19 — Tear-off requires a restoration story.** JetBrains distinguishes floating tool windows from independent windows and supports moving tools into other frames. Ara's saved layouts should include floating bounds, monitor identity and docking destinations, with off-screen recovery and Reset layout. Persist semantic panel instances so referenced inspector/asset views reopen meaningfully. [Modes](https://www.jetbrains.com/help/idea/viewing-modes.html), [arrangement](https://www.jetbrains.com/help/idea/manipulating-the-tool-windows.html)
- **I20 — Maximize must be reversible from every panel.** Unity uses **Shift+Space** and Blender **Ctrl+Space**. Unity's issue tracker records shortcuts failing during a held camera gesture. Ara should provide a visible Restore action, a bindable toggle, and consistent routing during viewport capture; restoration must recover exact prior splits. [Unity issue](https://issuetracker.unity.com/issues/11937), [Blender](https://docs.blender.org/manual/en/4.5/interface/window_system/areas.html)
- **I21 — Splitter geometry needs its own spec.** Ara proposal: a **1 px visual separator**, **8 px total hit band**, and starting minimums of **180 px** for a tree, **260 px** inspector and **320 px** viewport; permit scrolling/collapse when font scaling exceeds these. These are test values, not published competitor minimums. Use resize cursor feedback and avoid stealing nearby field input. [Scalable-layout precedent](https://plugins.jetbrains.com/docs/intellij/ui-faq.html), [density precedent](https://www.jetbrains.com/help/rider/IDE_Viewing_Modes.html)

### Palette, search and menus

- **I22 — Search should teach the interface.** VS Code's Cmd/Ctrl+Shift+P opens commands and displays shortcuts; Blender F3 shows menu locations; Unity Search reaches assets, menus, packages and logs, with Tab suggestions and recent queries. Ara results should show name, category, target, shortcut and disabled reason, with separate scopes for commands and content. [VS Code](https://code.visualstudio.com/docs/editing/getting-started/userinterface), [Blender](https://docs.blender.org/manual/en/4.0/interface/controls/templates/operator_search.html), [Unity](https://docs.unity.com/en-us/engine/6000.0/manual/unity-editor/editor-navigating-managing/editor-searching/search-overview/search-window-reference)
- **I23 — Rank helpfully without making results unpredictable.** VS Code documents persistent most-recently-used commands; Blender 4.0 promotes recently searched items. Ara proposal: exact/prefix matches first, then fuzzy matches, with recency/frequency as bounded tie-breakers. Empty queries show recent/contextual commands; destructive commands never win merely through frequency. This ordering is proposed, not a documented competitor algorithm. [VS Code MRU](https://code.visualstudio.com/updates/v1_14), [Blender](https://developer.blender.org/docs/release_notes/4.0/user_interface/)
- **I24 — Put frequent commands at the point of work.** Linear's contextual menus expose shortcuts without visiting Cmd/Ctrl+K; Blender's **Q** Quick Favorites accepts commands through their context menus. Ara should allow pinning commands/properties and show shortcut labels in palettes, menus and tooltips, all backed by the same command registry. [Linear](https://linear.app/now/invisible-details), [Blender](https://docs.blender.org/manual/en/4.5/interface/tool_system.html)
- **I25 — Submenus need directional forgiveness.** Linear describes a safe triangle between the pointer and submenu that prevents diagonal travel from closing it. Baymard's original web-navigation study recommends **300–500 ms** hover delays; that is not a native-editor timing specification. Ara proposal: start at **200 ms** submenu opening, immediate click opening, and directional grace; test mouse and trackpad paths. [Linear](https://linear.app/now/invisible-details), [Baymard](https://baymard.com/research-articles/dropdown-menu-flickering-issue)
- **I26 — Mnemonics and shortcuts serve different jobs.** JetBrains distinguishes underlined mnemonic letters from global command shortcuts and documents Alt activation on Windows/Linux. Ara should implement arrow-key menu navigation, Enter, Escape, platform mnemonics and visible accelerator labels, resolving conflicts centrally rather than assigning keys independently in each panel. [Source](https://plugins.jetbrains.com/docs/intellij/mnemonics.html)

### Viewport and inspector

- **I27 — Keep camera and rendering state discoverable.** UE 5.6 exposes camera speed and scalar, projection, transform tools, local/world coordinates, snapping and performance categories in stable groups. Mouse-button-plus-wheel adjusts camera speed. Ara should show current speed during navigation, with an orientation widget, frame-selected action and optional stats overlay. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/viewport-toolbar?application_version=5.6)
- **I28 — A viewport must reveal nonstandard preview state.** Epic adds actionable warnings when realtime is disabled or scalability differs from defaults; clicking can restore defaults. Ara should similarly surface paused rendering, non-game quality, debug view and isolated visibility as compact state indicators, rather than leaving users to explain an unexpectedly wrong-looking scene. [Source](https://dev.epicgames.com/documentation/en-us/unreal-engine/viewport-toolbar?application_version=5.6)
- **I29 — Component headers are a complete control surface.** Unity supports enabling/disabling components, folding, contextual copy/paste/remove and drag reordering with an insertion marker. Ara proposal: header = disclosure, type icon/name, enable state where supported, help and overflow; retain accessible labels and avoid initiating reorder from the disclosure/toggle hit areas. [Component management](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-gameobjects/unity-components/inspector-manage-components), [reorder precedent](https://docs.unity3d.com/es/current/Manual/UsingTheInspector.html)
- **I30 — Add-component search should explain applicability.** Unity provides Add Component and component documentation links; dependencies can prevent removal. Ara proposal: search by type/name/description, list recent choices, show a short purpose and dependency effects, and disable impossible additions with a reason. Adding with Enter should preserve scroll and focus the new component. [Source](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-gameobjects/unity-components/using-components)
- **I31 — Prefab modification is semantic state, not decoration.** Unity marks overrides with a blue margin and bold values; added components receive a plus badge. Ara should use persistent field-level provenance with a context menu for Revert, reveal source and inspect change, distinguishing inherited, overridden, animated, mixed and agent-modified states without relying on one color. [Source](https://docs.unity.com/en-us/engine/6000.6/manual/working-with-gameobjects/prefabs/override/prefab-instance-overrides)
- **I32 — Copy must work at field and component scope.** Unity supports component duplication versus pasting values into an existing component; its field clipboard support includes vectors, colors, references, gradients and curves in text form. Ara should preserve types, reject incompatible pastes explicitly, and provide Copy value and Copy property path as separate actions. [Component scope](https://docs.unity.com/en-us/engine/6000.3/manual/working-with-gameobjects/unity-components/using-components), [field scope](https://discussions.unity.com/t/improved-clipboard-copy-paste/778043)
- **I33 — Filtering must leave an escape route.** Epic's historic UE-42428 describes modified-only filtering hiding even the controls needed to turn it off. Ara should keep search/filter controls outside the filtered body, with active-filter chips, clear-all, a useful empty state and search across collapsed categories. [Source](https://issues.unrealengine.com/issue/UE-42428)

### Asset browser, console, tasks and history

- **I34 — Asset browsing needs both identity and previews.** UE documents breadcrumbs, history, sources, collections and filters; Unity offers the thumbnail/list slider. Ara should preserve stable selection while switching view modes, support favorites and type chips, and reveal an asset from scene/inspector references. Thumbnail generation must not block browsing. [UE](https://dev.epicgames.com/documentation/en-us/unreal-engine/content-browser-interface-in-unreal-engine?application_version=5.5), [Unity](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/project-view)
- **I35 — Preview richness should be opt-in and bounded.** UE offers thumbnail-size settings and real-time previews; Painter demonstrates typed drag creation. Ara proposal: static cached thumbnails first; on-demand material/model/audio preview; valid scene/inspector drop highlighting; import states queued/importing/ready/failed with retry. Keep source files visible and selectable before their derived previews finish. [UE settings](https://dev.epicgames.com/documentation/unreal-engine/content-browser-settings-in-unreal-engine?lang=en-US), [Painter](https://experienceleague.adobe.com/en/docs/substance-3d-painter/using/interface/layer-stack/creating-layers)
- **I36 — Console controls must survive small widths.** Unity supports duplicate collapse, severity filters, search, source navigation, Clear on Play and Error Pause; UUM-17923 documents controls disappearing below **420 px**. Ara should overflow secondary actions instead of losing search, preserve duplicate counts/timestamps, and distinguish local logs from player/client sources. [Manual](https://docs.unity.com/en-us/engine/6000.5/manual/unity-editor/editor-windows-views-reference/console), [width bug](https://issuetracker.unity.com/issues/17923/error-pause-player-logging-and-the-searchbar-tools-disappear-when-the-console-window-is-below-420px-width)
- **I37 — Progress belongs in a persistent task center.** Unity exposes parent/child tasks, status-bar aggregate progress, elapsed/remaining time, completed/failed states and cancellation where supported. Ara should show job ownership, affected asset/project and cancellation scope; a task may finish without requiring the human to dismiss a dialog. [Source](https://docs.unity.com/en-us/engine/6000.5/manual/unity-editor/editor-windows-views-reference/background-tasks-window)
- **I38 — Toast lifetime is different from task lifetime.** Slate notifications expose expiry, fades, buttons and persistent versus fire-and-forget behavior. Ara proposal: brief completion toasts link to durable task records; failures persist in Problems/task history; deduplicate bursts; never move keyboard focus for background notifications. No universal UE toast duration is asserted here. [Source](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Slate/Widgets/Notifications/FNotificationInfo?application_version=5.5)
- **I39 — Undo should be inspectable.** Blender provides a named Undo History and **F9** to adjust the last operation's parameters. Ara proposal: show a chronological, searchable transaction list with actor, object, operation and time; group an entire scrub into one undo item and offer per-agent-turn recovery separately from global history navigation. [Source](https://docs.blender.org/manual/ar/4.5/interface/undo_redo.html)
- **I40 — Play mode needs persistent peripheral cues.** Unity lets users tint the entire editor while playing. Ara should combine optional tint with a clear Play/Pause/Step cluster, textual mode/session labels, focused-client identity and an explanation of temporary versus persisted edits. Color alone is insufficient, especially for multiplayer Play and color-vision differences. [Unity](https://docs.unity.com/en-us/engine/6000.5/manual/unity-editor/editor-settings-reference/preferences/colors), [non-color cue principle](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 5. Visual design, motion, accessibility and density

- **V01 — Use semantic elevation, not arbitrary panel grays.** Linear's theme model and JetBrains' named theme-color guidance support distinct window, panel, input, popup, hover and selected roles. Ara proposal: start with **four elevation roles**, emphasize boundaries through small fill differences, and add borders where separation remains ambiguous. These are roles, not permission to replace Ara Dark/Light colors. [Linear](https://linear.app/now/how-we-redesigned-the-linear-ui), [JetBrains](https://plugins.jetbrains.com/docs/intellij/ui-faq.html)
- **V02 — Preserve state readability in compact controls.** Figma restored visible blend labels and expanded constraints after UI3 feedback. Ara should spend space on current values, selected-object identity and active mode; use icons for familiar actions with text/tooltips available. A borderless style must not make editable fields indistinguishable from labels. [Source](https://www.figma.com/blog/our-approach-to-designing-ui3/)
- **V03 — Typography has a concrete professional-tool baseline.** JetBrains documents **Inter 13** for main UI, **12** for secondary text, and paragraph line height **default +3**; styles scale relative to the user-selected size. Ara proposal: **13 px labels/values**, **12 px secondary text**, **16–18 px line height**; reserve **11 px** for optional metadata, never essential input. [Source](https://plugins.jetbrains.com/docs/intellij/typography.html)
- **V04 — Icon artwork and hit targets are separate dimensions.** JetBrains specifies **16×16** action/file icons, a **14×14** visible area within the standard artboard, and **20×20** New UI tool-window icons or **16×16** in Compact mode. Ara can use 14–16 px artwork inside larger targets; do not equate a 16 px icon with a 16 px clickable box. [Style](https://plugins.jetbrains.com/docs/intellij/icons-style.html), [New UI](https://plugins.jetbrains.com/docs/intellij/icons.html)
- **V05 — Row heights are proposed, not measured competitor constants.** Start Ara at **24 px** standard tree/property rows, **20 px** compact and **28 px** comfortable; derive heights from font metrics and vertical padding at higher scales. Rider documents compact mode qualitatively, but the reviewed sources do not establish a universal 20–28 px editor standard. [Source](https://www.jetbrains.com/help/rider/IDE_Viewing_Modes.html)
- **V06 — Density and scaling must be independent.** Blender scales fonts/buttons relative to detected DPI and offers Thin/Default/Thick line widths; Godot exposes theme contrast/borders and Zed separates UI/code/agent fonts. Ara should offer compact/standard/comfortable spacing plus UI scale, preserving usable labels, splitters, menus and dock targets at enlarged settings. [Blender](https://docs.blender.org/manual/en/4.5/editors/preferences/interface.html), [Godot](https://docs.godotengine.org/ja/4.5/classes/class_editorsettings.html), [Zed](https://zed.dev/docs/visual-customization)
- **V07 — Contrast applies to states and small text.** WCAG's useful reference thresholds are **4.5:1** for ordinary text and **3:1** for large text; control boundaries and meaningful graphics have separate non-text contrast requirements. Use these as Ara design targets, not a claim of web conformance for a native editor. Check hover, inactive selection, modified fields and disabled explanations in both themes. [Text](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [controls](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- **V08 — Focus must remain visible and distinct from selection.** WCAG 2.2's AAA focus appearance reference uses an area equivalent to a **2 CSS px perimeter** and **3:1** state contrast. Ara proposal: a clear keyboard-focus ring without requiring every pointer click to show one; maintain accessible focus through recycled rows and popup dismissal. [WCAG](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html), [Godot 4.6 focus behavior](https://godotengine.org/releases/4.6/)
- **V09 — Small dense rows need explicit accessibility alternatives.** WCAG 2.2 AA describes **24×24 CSS px** pointer targets with spacing/other exceptions. Ara's proposed 20 px compact rows therefore require deliberate target-spacing review and a comfortable mode; keyboard alternatives alone do not automatically satisfy the target-size criterion. Support named controls, value/state announcements and non-drag alternatives. [Source](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- **V10 — Use short motion only where it communicates continuity.** WinUI publishes **83 ms**, **167 ms**, and **250 ms** control durations. Ara proposal: **83–120 ms** hover/focus fades and **120–167 ms** popups; at most **250 ms** for infrequent layout transitions. These Ara choices are extrapolations, not measured Linear/Figma defaults. [Source](https://learn.microsoft.com/en-us/windows/apps/design/motion/timing-and-easing)
- **V11 — Direct manipulation should follow input immediately.** Ara proposal: no tweening of scrub values, gizmos, drag previews, text caret, tree selection, splitter position or wheel scroll response; avoid unrequested smooth camera movement. Respect reduced motion, stop finished progress animations, and avoid idle pulsing. This follows the need to disable nonessential interaction-triggered motion, rather than a claim that all reference tools behave this way. [Source](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

## 6. AI-agent-in-the-editor UX

- **A01 — Cursor demonstrates applied edits plus recovery.** Agent edits apply while it works, with diff review, rejection and Stop; Restore Checkpoint reverts later agent changes without removing conversation messages. Ara can use an activity feed and entity/property diff view without making a review gate the default. [Source](https://cursor.com/help/ai-features/agent)
- **A02 — Checkpoint scope must be explicit.** Cursor's checkpoint docs distinguish temporary local agent snapshots from Git and state that manual edits are not tracked. Ara should state whether Undo turn reverses only that author's ops, which objects are affected, and whether later edits prevent particular inverses. Never imply a turn checkpoint restores every external side effect. [Source](https://docs.cursor.com/en/agent/chat/checkpoints)
- **A03 — Zed makes following an agent opt-in.** Its crosshair follows the agent reading/editing files; Review Changes opens a multi-buffer view and an accordion lists modified files. Ara proposal: a Follow action frames the agent's current object/camera only when chosen; passive presence must not hijack the human's selection or camera. [Source](https://zed.dev/docs/ai/agent-panel?highlight=%7Bbuffer)
- **A04 — Turn recovery and steering should be near the conversation.** Zed exposes Restore Checkpoint at the initiating message and supports queued/steered messages. Ara should attach Undo turn, changed-object count, execution status and Stop to each turn, with expandable detailed operations rather than rendering every internal tool event at full height. [Source](https://zed.dev/docs/ai/agent-panel?highlight=%7Bbuffer)
- **A05 — Copilot separates recovery scopes.** VS Code documents individual/file/all pending-edit undo, editing an earlier request, restoring checkpoints and source-control discard. Checkpoints can also rewind conversation, unlike Cursor's behavior. Ara should name recovery actions precisely: Undo this turn, Undo field edit and Restore document revision are materially different operations. [Source](https://code.visualstudio.com/docs/agents/run/review-code-edits)
- **A06 — Figma's AI output remains ordinary editable content.** First Draft produces editable designs from libraries; the newer agent can reference library components/styles/variables using `@`, with Undo in chat. Ara should expose selected entities/assets as explicit prompt context and create ordinary typed engine content that all existing tools can inspect and edit. [First Draft](https://help.figma.com/hc/en-us/articles/23955143044247-Use-First-Draft-with-Figma-AI), [agent](https://help.figma.com/hc/en-us/articles/37998629035799-Work-with-the-Figma-agent-in-design-files)
- **A07 — Unity's assistant exposes tool activity and asset attribution.** Unity describes Ask/Plan/Agent modes, expandable activity entries with parameters/results, reversible steps and metadata on generated assets. Borrow visible execution and attribution; do not infer that every published AI tool has identical undo guarantees or require Ara users to approve every step. [Source](https://unity.com/blog/unity-ai-assistant-ask-plan-agent-mode-explained)
- **A08 — Unreal 5.7 has a contextual assistant, not just gameplay AI.** Epic documents a slide-out assistant for questions, generated C++ and step-by-step guidance; hovering a control and pressing **F1** starts contextual help. This source does not establish arbitrary scene editing or per-turn undo. Ara should offer Explain this field with schema/docs context and separately identify mutation-capable agents. [Source](https://www.unrealengine.com/news/unreal-engine-5-7-is-now-available)
- **A09 — Presence should identify the actor and scope.** Figma separates multiplayer cursors, following and Spotlight; following shares canvas position, not every sidebar action. Ara proposal: show agent name, current task, document/object, running/waiting/failed/completed state and optional selection outline; retain authorship in history after transient presence disappears. [Source](https://help.figma.com/hc/en-us/articles/360040322673-Present-to-collaborators-using-spotlight)
- **A10 — Immediate editing still needs understandable collisions.** Ara proposal, following D24: hold an agent's same-field mutation only until the human's active gesture ends, then apply it; show a nonblocking overwrite notice with both authors and a history link. Changes remain immediate and attributed. The need is supported by Unity's gesture-loss failure and agent recovery precedents, not by a claim those products implement Ara's collision policy. [Gesture evidence](https://issuetracker.unity.com/issues/10480/changing-transform-values-in-search-window-inspector-loses-focus-while-dragging-and-stopping-mouse-without-releasing-dragging-action), [recovery precedent](https://docs.cursor.com/en/agent/chat/checkpoints)

## Top 40 design rules for Ara

These are proposed Ara requirements derived from the findings above; linked finding IDs carry their external evidence.

1. Keep one command identity across menus, shortcuts, palettes, context actions and agents. **E24, I22, I26.**
2. Default to a stable scene-centered layout with full-height hierarchy and inspector; provide reversible focus. **E15, E17, I20.**
3. Save floating-window layouts and recover windows that were on disconnected monitors. **I19.**
4. Show both docking intent and the full resulting panel rectangle before release. **I18.**
5. Honor platform drag thresholds; never tear off a tab from click jitter. **I17.**
6. Give thin splitters generous hit areas and scale their minimums with text. **I21, V06.**
7. Preserve stable entity IDs through selection, reloads, filtering and row recycling. **P02, E12, I14.**
8. Benchmark trees with 100k items; virtualize and separate visual updates from structure. **I14, I16.**
9. Implement complete tree keyboard navigation, type-ahead and platform rename. **I09–I11.**
10. Keep focus, active row, range anchor and multi-selection visibly distinct. **E21, I10, V08.**
11. Keep ancestors in filtered trees and restore previous expansion when clearing. **I15.**
12. Separate synchronization from automatic reveal; always offer Reveal selected. **P10.**
13. Distinguish before/after/inside drops, and include hover expansion and edge scrolling. **I12–I13.**
14. Give names remaining column width; make extra hierarchy columns optional. **E09, P01.**
15. Provide direct keyboard commands for hierarchy, property and asset search. **P08, I22.**
16. Keep search controls visible when filters produce zero results. **I33.**
17. Show useful values directly; never require a tooltip to read an enum state. **E22, P11, V02.**
18. Separate numeric typing from scrubbing and tune sensitivity per unit. **I01–I02, P09.**
19. Support precision modifiers, expressions, units and continuous relative dragging. **I02–I05.**
20. Preserve mixed-value semantics and define absolute versus relative multi-edits. **E07, I07.**
21. Make linked-scale semantics explicit, including mixed and zero-axis behavior. **I06.**
22. Keep active typing/drags stable across search and agent updates. **P03, A10.**
23. Expose per-field reset, copy/paste, provenance and documentation. **E01, E13, I07, I31–I32.**
24. Give component headers clear collapse, enable, help, menu and reorder affordances. **I29–I30.**
25. Show override state with shape/text as well as color. **I31, I40, V07.**
26. Provide fuzzy command search with context, shortcuts and predictable recent ranking. **I22–I24.**
27. Protect diagonal submenu travel and support full keyboard menu navigation. **I25–I26.**
28. Keep viewport tool groups stable and show nonstandard rendering/camera state. **E05, P04–P05, I27–I28.**
29. Offer asset list/grid density, breadcrumbs, favorites and type filters. **E10, I34.**
30. Generate previews asynchronously; keep import state and retry attached to assets. **P06, I35.**
31. Preserve console search and severity controls at narrow widths; collapse duplicates with counts. **I36.**
32. Put background work in a persistent task center; use nonblocking toasts as links. **I37–I38.**
33. Make undo history inspectable; one continuous gesture produces one transaction. **I39.**
34. Mark Play mode with text and optional tint, including focused multiplayer client. **I40.**
